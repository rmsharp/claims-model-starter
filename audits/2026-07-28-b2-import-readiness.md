## 1. Secrets attestation — two negative proofs

Both commands below are exactly reproducible; re-run them to re-confirm before any import. Both
were re-run fresh this session (not trusted from §2.8's original write-up) after
`git fetch origin '+refs/heads/*:refs/remotes/origin/*'` — dragon #14: a history-wide claim without
a preceding fetch understates what's actually in every ref.

### 1.1 No credential FILE has ever entered git history

```bash
git fetch origin '+refs/heads/*:refs/remotes/origin/*'
git rev-list --all --objects | awk '{print $2}' | grep -iE "\.env|secret|credential|\.pem|id_rsa"
```

**Result (2026-07-28):**
```
.env.example
.env.example
.env.example
```
Three hits, all the same path (`.env.example` recurs across commits as the file was edited over
time — each entry is a distinct blob for the same tracked path, not three different files). No
`.env`, no `*.pem`, no `id_rsa`, no file literally named `secret*`/`credential*`, in any commit on
any ref. **No history rewrite is needed on secrets grounds.**

### 1.2 Zero committed secret VALUES — two orthogonal proofs

**Proof A — credential-shape content scan, full history, real-token-length regex** (distinct from
§1.1: this greps file *contents* across every diff ever committed, not filenames):

```bash
git log --all -p | grep -oE \
  "ghp_[0-9A-Za-z]{20,}|glpat-[0-9A-Za-z_-]{20,}|sk-ant-[0-9A-Za-z_-]{20,}|AKIA[0-9A-Z]{16}|-----BEGIN[A-Z ]*-----" \
  | sort | uniq -c | sort -rn
```

**Result (2026-07-28):**
```
      7 sk-ant-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
      7 glpat-xxxxxxxxxxxxxxxxxxxx
      6 ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```
Zero `AKIA...` (AWS access key shape) and zero `-----BEGIN...-----` (PEM block) hits anywhere in
history. The three hits above are all-`x` placeholder fills at real-token length — traced (via
`git log --all --oneline -S"<string>" --name-only`) to exactly four paths, all documentation:
`.env.example`, `docs/tutorial.md`, and their built-site copies on `gh-pages`
(`search/search_index.json`, `tutorial/index.html`, generated by `mkdocs build` from
`docs/tutorial.md`). No real credential value — as opposed to a placeholder shaped like one — has
ever been committed.

**Proof B — entropy scan, full history** (gitleaks v8.30.1, default ruleset, includes
keyword-gated regex rules for major providers plus an entropy-gated `generic-api-key` rule):

```bash
gitleaks detect --source . --report-format json --report-path gitleaks-report.json \
  --redact -v --no-banner --log-opts="--all"
```

**Result (2026-07-28):** `385 commits scanned` / `1` leak found — see §2, item 10 below
(`ROADMAP.md:65`), a confirmed false positive (a model identifier, not a credential). With
`.gitleaksignore` in place (this packet), the same command reports `no leaks found`.

**Why two proofs, not one:** Proof A is a precise, length-strict grep for the four provider token
shapes explicitly named in `docs/planning/enterprise-migration.md` §2.8. Proof B is a
general-purpose, keyword+entropy scanner that would also catch a real secret that doesn't match
any of those four specific shapes (e.g., a database password, a bare API key with no recognizable
prefix). Together they cover both "does a known-shape token appear" and "does anything
suspiciously random appear," which is the same two-proof structure §2.8 specifies.
